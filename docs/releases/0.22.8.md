# Instance 0.22.8

The Linux installers now write `Restart=always` for the agent service, so an
outside termination brings the same service back even when the agent handles
the signal and exits cleanly. A stop requested through systemd still leaves it
stopped. The enrolled update helper also restarts after an outside SIGTERM;
container services, container bridges, macOS and Windows policies are unchanged.

Fresh consumer installations bundle the published Runtime 0.15.9. It includes
the tool-permission fixes from 0.15.8 and recoverable errors for unlisted tool
names, including the Copilot provider path. Every platform's package and binary
are pinned by hash. Copilot remains an optional Unix provider: its matching
Python bridge and pinned SDK are installation-owned, separately delivered
inputs rather than part of the default native engine bundle. Existing
installations keep their selected engine, model,
accounts, configuration, sessions and work; engine adoption uses the normal
installation update path.

An application update alone does not replace an existing service definition or
remove a local restart override. Owners should verify the installed unit's
policy through their normal installation-maintenance path before removing an
override. Restart behavior remains subject to the enabled service, available
user manager and the manager's restart limits; it does not replay uncertain work.
