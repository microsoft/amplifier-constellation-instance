# Instance 0.22.5

Existing Linux Incus installations can enroll an independent host updater using
their actual guest home, binary and system services. The adapter reuses the
existing update API, frozen plans, recovery journal and experience participants.
Guest and agent identities stay pinned, credentials stay inside the guest, and
only the enrolled Instance executable is updated. Custom engines and guest images
are unchanged.

Helper refresh supports the guest boundary and resumes interrupted publication
before accepting more work. Connected experiences still need their own qualified
prepare, verify and restore participants before automatic installation is enabled.
See [existing Incus guests](../updates.md#existing-incus-guests) for enrollment and
its limits. Native installation behavior, Runtime 0.15.6 and dependency pins are
unchanged.
