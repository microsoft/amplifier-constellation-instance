# Agent Instance 0.22.0

New consumer bundles contain the native Instance executable, a private pinned
Python distribution, and the checksummed Constellation Runtime 0.15.4 release.
They cover Windows x64/ARM64, macOS Intel/Apple Silicon, and Linux x64/ARM64.
The fixed `agent-instance setup` command reuses the existing installer without
WSL, a compiler, Git, Node, or a machine-wide Python. An optional fleet client
can use this same entry point.

Each installation retains its executable, interpreter, engine, licenses and
private state after the download folder is removed. Setup copies no provider
account implicitly. Binary updates retain the recorded private interpreter;
setup update and rollback preserve the selected engine, credentials, identity
and history. No ACP or task-authority interface changes.

The native package checks reject wrong-platform or changed bytes and external
Windows VC++ runtime dependencies; private Python includes its own required
DLLs. Fixed Python invocations use UTF-8 for non-ASCII names and paths. Linux
startup uses a valid systemd working-directory directive. See
[native platforms](../native-platforms.md) for the exact setup interface.

Linux automatic startup requires an existing user service manager. Browser
password sign-in also needs the documented explicit PAM-policy installation;
setup does not write system authentication policy. Mac downloads remain unsigned.
Windows account policies still govern password logon; Hello PINs and biometrics
are not substitutes for this endpoint. Installing an engine does not establish
model-provider access. See [validation](../validation.md#consumer-bundle-validation)
for the distinction between native package, startup and provider coverage.
