# Agent Instance 0.22.10

An agent running under a dedicated Unix account can now let its owner sign in
with their normal host account through an existing private host PAM bridge.
This makes the agent's settings, including approval choices, accessible without
creating another password or changing the account that runs the agent.

The option is off by default. Existing local account sign-in is unchanged.
Administrators can configure one fixed account and socket using
[`server.host_pam`](../host-pam.md). Instance does not create the host bridge,
copy credentials, change socket permissions, or fall back to another login method
if the bridge refuses. Windows does not accept this Unix-only option.

Before reverting to an older Instance version, remove `server.host_pam` through
the supported configuration path. Older versions reject that field; they do not
silently use a different sign-in method.

Changing the sign-in account, socket, or PAM service invalidates existing browser
sessions and prevents an earlier pending login from creating a new session.
The installation's resource owner, ACP credentials, selected engine, approval
policy, work and budgets remain unchanged. This update does not enable automatic
approvals or add remembered rules.

The bundled Runtime remains 0.15.10. Existing installations keep their selected
engine. Host bridge configuration and reachability remain installation-specific;
package qualification does not establish that a particular owner's host login
has been configured or tested.
